# Photo-first parts inventory

Inventory extends the facility identity with an optional versioned inventory collection. Old packages without it mean an empty inventory; no production seed parts or quantities are introduced. Existing facility persistence, authenticated administrator commits, technician proposals, backups, and publication transport remain the authority.

Parts have stable IDs, descriptive and purchasing fields, structured storage locations, photo references, reviewed label text, machine compatibility links, and separate alternate-part links. Machine links reference existing assets in the same package. Exact identity and compatibility are separate facts. Verified compatibility requires a written source. Part records can be archived, preserving their history.

Stock is an append-only ledger, starting at zero. Receive, issue, return, reserve, release, adjustment, disposal, and physical count events retain actor, timestamp, reason, and optional machine. Each event has an idempotency ID and a preceding ledger version. Available stock is on-hand less reservations. Counts and adjustments cannot erase reservations. A stale proposal cannot overwrite intervening stock events. Concurrent publication edits to a part's ledger require reconciliation rather than automatic event concatenation. The existing publication revision compare-and-swap rejects stale remote writes. Offline balances describe this device's last synchronized records; synchronization is required before relying on shared availability.

Photos use existing facility-scoped attachment storage. Each reference records a role (part, label, package, barcode, location, installed reference). Existing publication access policy applies; local-only files stay local in portable exports. Files are uploaded only through the existing configured publication backend. File selection/camera capture is available without AI. Extraction, if supported by the environment, produces editable suggestions with visible source text, never verified facts. Manual text entry remains available. Barcode detection is progressive enhancement, with typed code entry always available.

The Parts Inventory workspace has focused Parts, Add Part, Find for Machine, Locations, Low Stock, Activity, and Advanced views. Equipment and troubleshooting entry links preserve machine context. Search includes identifiers, descriptions, tags, location, specifications, and transcribed label text. Machine results distinguish verified spares, approved alternates, and unconfirmed possibilities. Stock actions remain explicit forms with reasons and review status.

Validation covers ledger integrity and idempotency, stale updates, facility references, backup migration, publication conflicts, technician review, photo capture and review, machine finding, issue and count history, and desktop/phone layouts. Existing mandatory regression and visual-contract checks remain unchanged.
